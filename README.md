# ONE DESK · 하나솔루션 경영지원 통합 플랫폼

경영지원(총무·회계·인사) 실무 경험을 바탕으로 기획하고, **HTML5 · CSS3 · Vanilla JavaScript**만으로 구현한
사내 경영지원 통합 웹 애플리케이션입니다. 서버·프레임워크 없이 브라우저 `localStorage`만으로 동작하는
정적 웹앱이며, GitHub Pages로 배포되어 있습니다.

## 기획 배경

경영지원 직무(회계·총무)로 일하며 반복적으로 느꼈던 실무 불편함 — 지출결의서의 수기 합산, 예산 초과 여부를
매번 눈으로 확인해야 하는 점, 적격증빙 수취 여부를 개별적으로 챙겨야 하는 점, 연차 일수를 손으로 계산하는 점 —
을 하나의 대시보드에서 해결하는 것을 목표로 기획했습니다. 실무 지식(전자결재 결재선 규정, 적격증빙 기준,
정액법 감가상각 등)을 화면 설계에 직접 반영한 점이 이 프로젝트의 핵심입니다.

기획·구현 과정에서 Claude 등 생성형 AI 도구를 적극 활용했습니다. 코드를 처음부터 직접 짜기보다, 문제를
작은 단위로 나눠 AI에게 요구사항을 명확히 전달하고, 나온 결과물이 실제 업무 흐름(전결 규정, 4대보험 요율,
근로계약서 필수 기재사항 등)에 맞는지 검증·수정하는 방식으로 만들었습니다.

## 권한 구조 — 전 직원용 + 경영지원팀 관리자용

실제 회사처럼 로그인 계정을 두 종류의 역할로 나눴습니다.

- **일반 직원**: 본인의 연차·근로계약서·결재 진행 상태만 열람. 지출결의서·휴가신청서를 본인 명의로 직접
  작성·상신할 수 있고, 기안자는 로그인 계정으로 자동 고정되어 임의로 바꿀 수 없습니다.
- **경영지원팀(관리자)**: 인사관리·전자결재·회계·CRM·자산관리 등 회사 전체 데이터에 접근하고, 결재를
  승인/반려 처리합니다. 로그인 계정이 없는 직원(예: 신규 입사 전 임시 등록자)의 문서는 관리자가 대신
  등록할 수 있는 경로도 남겨뒀습니다.

헤더의 **"일반 직원 보기 / 경영지원팀 보기" 토글**로 재로그인 없이 즉시 화면을 전환할 수 있어, 한 계정으로
양쪽 UX를 바로 시연할 수 있습니다. 로그인 자체는 이름(아이디)과 생년월일 앞 6자리(기본 비밀번호)로
하며, 로그인 후 마이페이지에서 비밀번호를 변경할 수 있습니다.

## 주요 기능

| 카테고리 | 핵심 기능 |
|---|---|
| **로그인 / 권한** | 이름+생년월일 6자리 기본 비밀번호 로그인, 헤더 토글로 즉시 역할 전환(일반 직원 ↔ 경영지원팀), 사이드바 "전자결재" 메뉴에 대기 건수 실시간 뱃지 |
| **대시보드** | (경영지원팀) 회사 전체 이번 달 수입/지출/순이익 KPI, D-Day 정산 마감 타이머(브라우저 알림 지원), 출근 현황, 결재 대기 문서 요약 / (일반 직원) 본인 잔여 연차·결재 대기 건수·이번 달 지출결의 합계 등 개인화된 요약 |
| **마이페이지** | 모든 로그인 사용자 공통 화면. 본인 연차 현황, 본인 근로계약서 열람(타인 것은 접근 불가), 본인 명의 지출결의서·휴가신청서 작성, 누적 상신/대기/승인/반려 건수 통계, 반려 시 사유 확인, 비밀번호 변경 |
| **인사관리 (HRM)** *(경영지원팀)* | 직원 CRUD, 근속연수 자동 계산, 근로기준법 기준 연차 자동 계산, 출근 상태 토글. **근로계약서 필수 기재사항 체크리스트**(근로기준법 제17조 기준 9개 항목 자동 판별), **4대보험 정산 계산기**(2026년 요율 기준 국민연금·건강보험·장기요양·고용보험·산재보험 근로자/사업주 부담금 계산) |
| **전자결재** | 지출결의서 작성 시 공급가액·부가세(10%)·합계 자동 계산, **금액 구간별 다단계 결재선 자동 판단**(30만원 이하 팀장 전결 → 100만원 이하 팀장·본부장 → 초과 시 대표이사까지), 승인 시 회계 장부 자동 반영, **반려 시 사유 필수 입력**(기안자 마이페이지에 노출). **휴가신청서**는 신청 시 잔여 연차를 미리 보여주고, 최종 승인되면 인사관리의 사용 연차가 자동 차감됨 |
| **회계·지출증빙** | 수입/지출 CRUD, 월별 카테고리 예산 게이지 바(80%/100% 경고), **AI 영수증 인식(OCR)**: 영수증 이미지를 첨부하면 Tesseract.js가 금액·날짜·상호명을 1차로 읽어 입력창에 채우고, 사용자가 결과를 확인·수정하는 구조(자동 인식을 맹신하지 않고 "AI 제안 → 사람 검증" 흐름을 그대로 구현), 적격증빙 체크리스트(3만 원 초과 건 세금계산서 수취 여부 판정), CSV(엑셀) 다운로드 |
| **고객·영업관리 (CRM)** *(경영지원팀)* | 리드→상담→제안→계약 파이프라인 칸반, 단계별 이동, 파이프라인/계약 금액 집계 |
| **재고·자산관리** *(경영지원팀)* | 자산 CRUD, **정액법/정률법 감가상각 선택 계산**, 안전재고 이하 품목 경고 |
| **데이터 백업/복구** *(경영지원팀)* | 서버가 없는 정적 사이트의 한계를 보완하기 위해 전체 데이터를 JSON으로 백업/복구 |

## 기술 스택

- **HTML5 / CSS3 / JavaScript (ES6+, 프레임워크 없음)**
- 데이터 저장: `localStorage` (모듈별 상태를 하나의 JSON으로 통합 관리), 로그인 세션은 `sessionStorage`(탭 단위)
- OCR: [Tesseract.js](https://github.com/naptha/tesseract.js) (CDN, 브라우저에서 직접 실행)
- 배포: GitHub Pages
- 폰트: Pretendard

## 폴더 구조

```
biz-suite/
├─ index.html            # 로그인 화면 + 사이드바 + 콘텐츠 영역 (탭 전환형 SPA)
├─ css/
│  └─ styles.css         # 디자인 시스템 (컬러 토큰, 카드, 테이블, 게이지, 칸반, 모달, 로그인 화면)
└─ js/
   ├─ storage.js         # localStorage 저장/로드, JSON 백업·복구
   ├─ seed.js             # 최초 실행 시 예시 데이터 (테스트 계정 포함)
   ├─ ui.js               # 포맷터, 토스트, 모달 등 공용 유틸
   ├─ auth.js             # 로그인/로그아웃, 역할(일반 직원·경영지원팀) 관리, 헤더 역할 토글
   ├─ app.js              # 라우팅, 초기화, 역할별 사이드바 표시, 결재 대기 뱃지
   ├─ dashboard.js        # 역할별로 분기되는 대시보드
   ├─ myinfo.js           # 마이페이지 (전 로그인 사용자 공통)
   ├─ hrm.js
   ├─ approval.js
   ├─ accounting.js       # 회계 + AI 영수증 OCR
   ├─ crm.js
   ├─ assets.js
   └─ settings.js
```

각 업무 모듈은 `Views.<key> = { title, subtitle, render(el) }` 형태로 독립 등록되며,
`app.js`가 사이드바 클릭 및 현재 역할에 따라 해당 모듈만 렌더링합니다. 모든 데이터는 하나의 `STATE` 객체로
관리되고, 변경 시 `persist()`를 호출해 `localStorage`에 즉시 저장됩니다.

## 알려진 한계 (정적 사이트 구조상의 제약)

- 서버가 없어 사용자 간 데이터가 실시간으로 공유되지 않습니다. 같은 브라우저 안에서 계정(역할) 전환은
  가능하지만, 다른 기기·브라우저의 사용자에게 즉시 알림이 가는 진짜 실시간 알림은 구조적으로 불가능합니다.
- 영수증 OCR은 완벽한 인식을 목표로 하지 않았습니다. 한글 영수증 인식률이 완벽하지 않을 수 있어, 인식 결과를
  사용자가 반드시 확인·수정하도록 설계했습니다.
